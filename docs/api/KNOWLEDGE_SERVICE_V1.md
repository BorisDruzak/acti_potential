# ACTI Knowledge Service: контракт потребителя v1

Этот контракт описывает обычного внешнего API-клиента ACTI Core. Модель,
embeddings, векторная БД и MCP-сервер для него не требуются. Потребитель получает
только разрешённые данные через HTTPS API; прямой доступ к PostgreSQL, файловому
хранилищу и внутренним storage keys не является частью контракта.

## Идентичность и область доступа

Сервисный API размещён под `/api/service/v1` и принимает Bearer-токен.
Существующий интерфейс `/api/v1` продолжает использовать пользовательскую
сессию и CSRF. Переданная рядом cookie не расширяет полномочия Bearer-клиента.

Администратор создаёт сервисную идентичность, явно выбирает реестры и операции,
выдаёт токен на 1–90 суток и может немедленно отозвать или заменить его.
Сервисная идентичность сохраняет обычный неизменный UUID пользователя, но не
имеет локального пароля и не предназначена для интерактивного входа.
Открытое значение токена возвращается один раз. Клиент хранит его в защищённом
хранилище секретов и передаёт только в заголовке Authorization, не в URL.

Действующая область — пересечение текущих разрешений сервисной идентичности,
области учётной записи и собственной области токена. Расширение учётной записи
не расширяет уже выданные токены. Сужение области, отзыв токена, его истечение
или отключение идентичности учитываются при следующем запросе. Отключение
учётной записи отзывает выданные токены; повторное включение требует нового.

Операции: `documents`, `files`, `content`, `relations`, `processes`, `knowledge`,
`numbers`, `execution`, `events`. Они разрешают чтение соответствующего API,
но не заменяют права реестра, документа или поля. Для получения оригинала
нужна операция `files`, для извлечённого текста — `content`. Администратор
конфигурации не получает автоматического доступа к содержимому.

## Точные версии и вложенные ссылки

UUID документа, файловой редакции, файла, extraction и блока различаются.
Номер metadata revision описывает реквизиты карточки и не является номером
файловой версии. Потребитель сохраняет выданные UUID и provenance вместе с
номером версии, не подменяет старую ссылку текущей редакцией.

Вложенные основания процесса, связи, оригиналы шаблонов и результаты исполнения
повторно проверяются по текущему actor. Разрешение на объект в одном реестре
не разрешает связанный документ в другом. Закрытая ссылка заменяется общим
признаком ограничения без раскрытия UUID, названия или текста источника.
Разрешённый каталог не гарантирует права на все упоминаемые им источники.

Ссылка на конкретный блок содержит идентичность документа, файловой версии,
файла и блока. Открытие такой ссылки в браузере повторно требует действующую
пользовательскую сессию и её права. Ссылка не является подписанным разрешением
и не переносит полномочия сервисного токена человеку.

Клиент должен проверять доступ перед каждым показом сохранённого фрагмента.
Событие или ранее успешный ответ не разрешают отдавать текст после отзыва прав.
Ответы API используют `Cache-Control: no-store`; долговременная внешняя копия
текста без отдельной политики актуализации/удаления не предусмотрена.

## Поверхность API v1

Все пути ниже относительны `/api/service/v1`; существующие ресурсы используют GET.
Поиск и retrieval принимают POST с типизированным JSON.
Машиночитаемый контракт: `backend/contracts/knowledge-service-v1.openapi.json`;
актуальная схема доступна также через `/openapi.json` с действующим токеном.

| Ресурс | Пути | Операция |
| --- | --- | --- |
| Карточки | `/documents`, `/documents/{id}` | `documents` |
| Опубликованная форма | `/form-schemas/{id}` | `documents` |
| Реквизиты | `/documents/{id}/metadata-revisions`, `/metadata-revisions/{revision_id}` | `documents` |
| Файловые редакции | `/documents/{id}/file-versions`, `/file-versions/{version_id}` | `files` |
| Оригинал | `/files/{id}`, `/files/{id}/download` | `files` |
| Извлечение | `/documents/{id}/content`, `/extractions/{id}/blocks` | `content` |
| Точный фрагмент | `/blocks/{id}` | `content` |
| Связи | `/documents/{id}/relations`, `/relations/{id}` | `relations` |
| Процесс и шаг | `/process-versions/{id}`, `/process-versions/{id}/steps/{step_key}` | `processes` |
| Шаблон и практика | `/template-versions/{id}`, `/cases/{id}` | `knowledge` |
| Номера | `/number-series/{id}`, `/number-series/{id}/entries`, `/number-entries/{id}` | `numbers` |
| Исполнение | `/execution/instances`, `/execution/instances/{id}` | `execution` |
| Изменения | `/events` | `events` |

Обычная страница: `{items, total, page, page_size}`. Фильтры списка карточек:
`registry_id`, `q`, `document_type_id`. Детальные параметры, допустимые размеры
страниц и структуры ресурсов определены OpenAPI. Feed имеет отдельный envelope,
описанный ниже. Не заменять его числовой пагинацией обычных списков.

Пользовательский cookie API имеет совместимые дополнительные каталоги:
`/api/v1/processes/catalog` (`registry_id`, `q`, `mode`, `page`, `page_size` до 100)
и `/api/v1/processes/{id}/version-catalog` (`mode`, `page`, `page_size` до 50).
Старые массивы `/processes` и `/processes/{id}/versions` сохранены. Содержание
`/api/v1/documents/{id}/content` сохраняет `items` и добавляет `total`, `page`,
`page_size` (20 по умолчанию, до 100), а также фильтр `file_id` для точной ссылки.
Поиск процесса учитывает видимые реквизиты опубликованной редакции; закрытые
черновики не влияют на результаты, total и границы страниц читателя.

## События и обработка

Изменение доменной сущности и запись transactional outbox входят в одну
транзакцию. Событие содержит `event_type`, `payload_version`, стабильный UUID
и минимальные идентификаторы; исходный текст, поисковый запрос, cookie и токен
не включаются. Внешний feed повторно авторизует объект и вложенные источники.

Доставка допускает повтор. Потребитель дедуплицирует по UUID события и своей
версии обработчика, фиксирует результат и checkpoint атомарно на своей стороне.
Событие служит поводом перечитать разрешённую точную редакцию, а не копией
данных и не гарантией сохранения доступа.

Feed выдаёт успешно обработанные события в порядке отдельного сохраняемого
номера публикации. Worker назначает номер под транзакционной блокировкой,
удерживаемой до commit; повтор сохраняет прежний номер. Время создания события
не служит checkpoint: транзакция производителя может завершиться позднее
другой транзакции с более новым timestamp. Старые обработанные события получают
порядок при миграции. Сам номер публикации внешнему клиенту не раскрывается.

Feed использует непрозрачные серверные bookmarks, связанные с токеном и
параметрами запроса. Они не содержат клиентского смещения или глобального
счётчика скрытых событий. Повторное чтение bookmark безопасно, но действующие
ACL могут изменить видимый набор. Пустая страница с новым bookmark не доказывает
отсутствие изменений во всём корпусе. Bookmark действует не более 15 минут
и не дольше токена. Истечение или изменение эффективной области даёт
`service_cursor_rejected`: начать новый обход с дедупликацией UUID событий.
Замена токена не переносит его bookmarks автоматически.

Envelope feed: `{items, next_cursor}`. В событии доступны `id`, `event_type`,
`payload_version: 1`, `created_at`, `object: {type, id, href}` и разрешённые
`origins` той же формы. Raw outbox payload не выдаётся. `page_size` не превышает
100; один запрос просматривает ограниченную порцию внутренней очереди.
Рекомендуемый интервал опроса — 5 секунд, в том числе после пустой страницы.
На один токен допускается до 2000 действующих bookmarks; обработчик должен
переиспользовать свою текущую цепочку, а не запускать постоянные новые обходы.

Внутренний worker сохраняет идемпотентные receipts, ограниченные повторы и
dead-letter состояние. Повтор оператором требует причины. Ошибка обработки
не даёт права публиковать неавторизованный payload. Новая служба доставки
для этого контракта не нужна.

## Ошибки и эксплуатация

Клиент сохраняет `X-Request-ID` ответа для диагностики, не журналирует секреты
и содержимое Authorization. Ошибки имеют машинный code и безопасное сообщение.
Недействующий токен даёт 401, запрещённая операция — 403, недоступный объект
не должен раскрывать свою идентичность. После 401 требуется новая авторизация;
после 403 нельзя повторять запрос с более широкими полномочиями автоматически.

Списки ограничены и пагинируются после применения ACL. Фильтры и идентификаторы
передаются согласно OpenAPI, а не произвольными SQL-выражениями. Потребитель
не выводит размер закрытого корпуса из `total` или границ страниц.

Показатели агрегируются по дню, реестру и типу операции. Поисковый текст,
пользовательский профиль, IP и отдельный путь просмотра в показатели не входят.
Сводка администратора и операторская очередь также ограничиваются текущими
правами на соответствующий реестр и объект.

Измеряются инструментированные операции получения данных, поиска и открытия,
а не весь HTTP-трафик. Глобальные, неизвестные, неразрешимые и недоступные события
не включаются в feed. Прежние события публикации шаблона без точного UUID версии
также пропускаются; новые публикации содержат этот UUID. Это ограничение истории
не заменяет первичную синхронизацию разрешённых ресурсов.


## Единый поиск и контекст (SEARCH-001)

`POST /search` использует тот же PostgreSQL-конвейер, что `POST /api/v1/search`
для сотрудников. Нужна операция `documents`; содержимое файлов дополнительно
требует `content` и обычное право download. Токен только с `files` не получает
поиск по тексту файлов. Сервисный режим всегда viewer. Закрытые поля и файлы
исключаются до ранжирования, подсчёта и курсора.

JSON: `query`, `scope` (`all`, `metadata`, `content`), `registry_ids`,
`document_type_ids`, `date_from`, `date_to`, `status`, `reg_number`, `filters`,
`fuzzy`, `sort`, `direction`, `version_scope`, `page_size`, `cursor`. Пустая
строка — просмотр разрешённых документов. Источники объединяются OR, фильтры
применяются AND. `sort=auto` означает релевантность для строки поиска и последние
изменения для просмотра. Сохраняются разрешённые сортировки конструктора.

`version_scope=current` выбирает последнюю редакцию каждого оригинала по
документу, полю и имени файла без учёта регистра; `all` включает прежние редакции.
Глобальный номер DocumentVersion является порядком загрузок и не заменяет
набор независимых вложений. Файл с другим именем — другой оригинал.

Ответ `/search`: `items` (document, score, match_count, matches), `total`,
`next_cursor`, `page_size`, `algorithm_version`. Курсор действует 15 минут,
привязан к actor, токену, запросу, режиму и профилю ранжирования. Права проверяются
заново; курсор не является снимком изменяющегося корпуса. Для продолжения
повторяют те же параметры с `next_cursor`; идентичность документа разрывает
равенство оценок. Диапазоны `highlights` задаются в UTF-16 для безопасного React
rendering: это текстовые позиции, а не HTML.

`POST /retrieval` принимает тот же JSON и требует `documents` + `content`.
Возвращает лучшие chunks разрешённой страницы документов, `document_total` и
тот же курсор. `GET /chunks/{chunk_id}` получает точный контекст,
`GET /chunks/{chunk_id}/neighbors?radius=1` — до двух соседей с каждой стороны
в той же extraction и версии алгоритма. Обе операции требуют `content` и заново
проверяют текущие ACL. Отзыв доступа не ждёт переиндексации.

Chunk содержит document_id, chunk_id, source_type, version_id, file_id,
extraction_id, block_ids, ranges (block_id/start/end в Unicode code points),
page/anchor, text, score, SHA-256, algorithm_version и citation. Для метаданных
version_id пуст, а metadata_revision и field_key указывают текущую редакцию
карточки. Текст файлов восстанавливается из точных диапазонов неизменяемых
блоков; контрольная сумма проверяется при чтении. Отдельных копий файлов или
текста chunks нет. Ссылки `/view?...` открываются с правами человека.

Существующие GET `/documents`, `/content/search` и экспорты остаются совместимы.
Сотрудник экспортирует те же условия через `/api/v1/search/export`; предел
экспорта 10 000 строк сохраняется, у самого поиска такого предела нет.
