## Ограниченный доступ к ACTI — PASS

Установлен отдельный root-owned helper с изолированным Python, абсолютными
путями исполняемых файлов и фиксированными командами. Обычная VM-учётная запись
наблюдения не состоит в Docker-группе. Её SSH-ключ ограничен источником,
`restrict` и forced command; sudo разрешает только точный helper без аргументов.
Файлы ключа, sudoers, helper и конфигурации недоступны этому читателю на запись.
Операторский SSH-ключ, пароль PostgreSQL и прикладная ACTI-учётная запись
наблюдателю не предоставлялись. Проверка SSH host key сохраняется.

Реальная проверка доверия и ограничения команды — **PASS**, закрытая квитанция
`observer-monitor-host-trust-and-confinement.json`, 09:45 UTC. Helper отдаёт только
версионированный Boolean JSON `acti-observer-v1`: неизвестное состояние остаётся
false; UUID, container IDs, содержимое очередей, личности, секреты и raw errors
в ответ не включаются. Запуск с аргументами и запуск без root отклоняются.

Чтение PostgreSQL касается только целевой ACTI: фиксированные агрегаты outbox
и просроченных extraction leases в read-only транзакции с ограничениями времени.
Redis используется только для GET heartbeat. Проверка файловых томов сверяет
точные mount/UUID до оценки свободного места. Backup-проверки читают защищённые
квитанции и состояние существующих systemd jobs/timers. Helper не исправляет
сервисы, не запускает backup, не меняет mounts и не обращается к SQL Server.

Эта проверка относится к конфигурации наблюдения и сохранению действующего

## Наблюдение и интерфейс — PASS

На стороне `web_ovpn` применён кандидат интерфейса `806c38`:
девять согласованных файлов и изменения observer. Это ограниченное применение
компонента, а не утверждение о публикации всей рабочей директории или main.
Существующий observer timer восстановлен в enabled/active;
закрытая квитанция — `observer-existing-timer-restored.json`.
Новый параллельный timer или механизм автоматического исправления не вводился.

После проверки настоящего FILESERVER и настройки отдельного ограниченного
читателя штатный сборщик подтвердил:

| Проверяемая часть | Фактическое состояние |
| --- | --- |
| ACTI: 12 Boolean проверок helper и 3 независимые HTTPS/OIDC проверки | 15 OK |
| Внешнее backup-наблюдение | 3 OK |
| Реальный браузер: навигация, восемь ролей, запреты и logout | PASS; ACTI и backup OK |
| Реальная остановка worker, критическое состояние и восстановление в браузере | PASS; тот же контейнер, остальные сервисы сохранены |

Первоначальные три ERROR были связаны с неверно выбранным backup-host и
отсутствием ограниченного читателя на настоящем FILESERVER. Исправлены только
host/user роли `acti_backup` и отдельная запись доверия; прежние шесть целей,
ACTI-цель, registry и остальные настройки сохранены. Общая роль file_server
не переиспользовалась. Итоговые квитанции: `monitor-repair-finalize-receipt.json`
и `observer-browser-healthy.json`, браузерная проверка 11:09:33 UTC.

На FILESERVER создан отдельный обычный локальный читатель с ключом только
сервера мониторинга. Его уникальный SSH Match разрешает фиксированную проверку;
пароль, PTY и forwarding запрещены. Реальные попытки заменить команду на
`whoami` и `cmd` возвращают тот же закрытый Boolean JSON; PTY, forwarding
и password-only отвергнуты. Для чтения Application добавлен только Allow ACE
mask 1 новому SID; прежние ACE, owner, group и SACL сохранены. Членства в
Administrators и Event Log Readers нет. Правила существующих пользователей
и отдельной SFTP-учётной записи backup сохранены.

Проверены полный синтаксис sshd, неизменность исходного префикса конфигурации,
глобальных auth gates и effective-конфигурации существующего оператора.
Effective `-T` для нового локального пользователя не считается доказательством:
на этой версии Windows/OpenSSH он зависает; доступ и запреты приняты по
настоящим SSH-соединениям. Перед временным перезапуском sshd удерживался
штатный ACTI backup lock; изменение имело независимый rollback и UTC fence.
Текущий sshd работает, временные helper-процессы завершены.

Три отключённых локальных читателя неуспешных установочных попыток удалены
с проверкой точных SID/описаний/квитанций и отсутствия ссылок в конфигурации.
Ещё один остаётся отключённым: Windows сообщает Loaded для его профиля;
принудительная выгрузка и изменение профиля не выполнялись. Он не имеет
действующего SSH-блока или Application ACE. Прикладной браузерный fixture удалён.

Реальная критическая проба: свежие UUID, исходный worker и версия приложения
закреплены; очередь и leases проверены read-only и пусты. Перед остановкой
worker включён собственный независимый recovery timer. В 10:17 UTC штатный
сборщик получил `worker_active=critical`; браузер подтвердил ACTI `critical`.
После восстановления того же worker сборщик получил все 15 ACTI checks OK,
браузер подтвердил ACTI `ok` в 10:18:34 UTC. Консервативная верхняя граница
недоступности worker — 49,083 секунды. Остальные пять контейнеров не менялись.

Квитанции: `observer-native-critical.json`, `observer-browser-critical.json`,
`observer-native-recovered.json`, `observer-browser-recovered.json` и
`final-native-recovery-summary.json`. Backup-роль оставалась ERROR во время
этой пробы; её успех этими квитанциями не утверждается. Повторный cleanup
тестового сценария обнаружил уже удалившийся собственный transient timer после
успешного восстановления. Отдельное read-only подтверждение установило healthy
worker и отсутствие активных временных units; будущая обработка этого случая
исправлена и проверена без повторной остановки приложения.

Браузер использовал отдельного временного обычного читателя и настоящие
серверные ответы: anonymous 303 на login, API без Bearer и с неверным Bearer 401,
управление пользователями 403, logout закрывает доступ. Ошибок страницы и
прикладных изменений данных — 0. Прежние два сигнала других серверов сохранены;
успех новых ACTI-проверок не означает исправление этих независимых проблем.
