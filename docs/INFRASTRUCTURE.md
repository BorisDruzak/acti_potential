# Инфраструктурная основа ACTI v3

Проверено 2026-10-15. Фактические параметры основной машины находятся в локальных
`PROJECT_CONTEXT.local.md` и `project.local.toml`, исключённых из Git.
Подключение: `ssh acti-v3`. Используется отдельный Ed25519-ключ вне репозитория.
Вход по ключу проверен также в `BatchMode=yes`; повышение привилегий через `sudo`
по-прежнему требует административной аутентификации.

## Разделение хранения

| Назначение | Диск | Точка монтирования | Формат | Метка |
| --- | --- | --- | --- | --- |
| ОС | 50 ГиБ | `/` и `/boot` | существующие LVM/ext4 | без изменения |
| PostgreSQL и WAL | 100 ГиБ | `/srv/acti/postgresql` | GPT/ext4 | `acti-postgresql` |
| Оригиналы и версии документов | 400 ГиБ | `/srv/acti/documents` | GPT/ext4 | `acti-documents` |

На каждом диске данных создан один выровненный раздел от 1 МиБ до конца диска.
До форматирования проверены размер, отсутствие разделов, сигнатур, монтирования
и использования в LVM. Системный диск не изменялся.

Монтирование записано в `/etc/fstab` по UUID с проверкой ФС (`0 2`). Для обоих томов
используются `noatime,nodev,nosuid`, для документов дополнительно `noexec`.
Резерв ext4 — 1% на томе PostgreSQL и 0% на томе документов.
Отображаемый доступный размер ниже номинального из-за метаданных файловой системы.

`nofail` не используется: оба тома обязательны для `local-fs.target`.
При отсутствии тома загрузка может потребовать восстановления через консоль ВМ.
Такой режим предотвращает незаметную эксплуатацию с потерянным диском данных.
Синтаксис UUID и поведение параметров описаны в [fstab(5)](https://man7.org/linux/man-pages/man5/fstab.5.html).

## Защита от записи на системный диск

Под точками монтирования расположены пустые каталоги `root:root`, режим `000`,
с атрибутом immutable. После монтирования используются права корня самого тома:
`0700` для PostgreSQL и `0750` для документов, пока оба принадлежат `root:root`.
Атрибут underlying-каталога не ограничивает запись на смонтированный том.
Атрибут описан в [chattr(1)](https://man7.org/linux/man-pages/man1/chattr.1.html).

Перед развёртыванием нужно назначить владельца на смонтированном томе согласно
реальному UID/GID выбранного PostgreSQL и приложения. Файлы БД не должны быть
доступны учётной записи приложения или всем пользователям. Не использовать `0777`.

Для будущих systemd-сервисов обязательны зависимости `RequiresMountsFor=` на их
тома. Перед запуском контейнеров проверять mountpoint и ожидаемый UUID; bind mount
каталога сам по себе не подтверждает наличие отдельного диска.
Бинарные документы не хранятся в PostgreSQL; доступ к ним идёт через backend
и предусмотренную roadmap абстракцию StorageProvider.

## Выполненная проверка

- Вход по SSH с ключом, отключённым интерактивным вводом и строгой проверкой host key.
- Проверка `/etc/fstab` через `findmnt --verify --verbose`; ошибок нет.
  Есть предупреждение для существующего swap-файла ОС, не относящееся к новым томам.
- Для каждого тома: временный файл, запись, `fsync`, чтение, сравнение и удаление.
- Размонтирование каждого пустого тома и подтверждение, что даже `root` не может
  создать файл в underlying-каталоге системного диска.
- Повторное монтирование по записи fstab с проверкой исходного UUID.
- Оба systemd mount unit активны и обязательны для `local-fs.target`.
- Исходный и итоговый fstab и инвентарь дисков сохранены в закрытом каталоге
  администратора на ВМ; точный путь записан в локальном контексте.

ВМ не перезагружалась; прохождение загрузки после reboot ещё не проверено.
PostgreSQL, runtime контейнеров и ACTI не установлены. Сервисные UID/GID,
конфигурация БД, резервное копирование и проверка восстановления относятся
к последующему развёртыванию платформенного ядра. Два тома одной ВМ не являются
резервной копией.
